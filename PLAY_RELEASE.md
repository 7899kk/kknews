# Google Play release preparation

Application ID: `com.karthikkilari.expiryradar` (confirm availability in your Play Console before your first upload). Version 1.0.0, code 1. Minimum API 28; compile/target API 36. New phone apps require API 36 from August 31, 2026 according to https://developer.android.com/google/play/requirements/target-sdk (verified October 12, 2026). Recheck at upload time.

## Signing
Never commit a keystore, signing passwords or `local.properties`. An unsigned release bundle may be generated by `./gradlew bundleRelease`; it is not upload-ready without your upload signing key. In Android Studio use Build → Generate Signed Bundle / APK → Android App Bundle. Create or select your private upload keystore outside this project. Enable Google Play App Signing in the Console; keep the upload keystore backed up securely. This project deliberately contains no signing credentials or automatically generated production key.

## Store text
Name: Expiry Radar
Short description: Track expiry dates offline and get reminders before items expire.

Full description:
Track it today. Save it before it expires.
Expiry Radar keeps expiry dates for groceries, skincare, medicines, household items, documents and warranties in one private, offline place.
• Add items and separate batches with their own dates.
• Scan barcodes locally and reuse previously entered product details.
• Photograph printed packaging dates, review OCR suggestions and confirm the correct date.
• Receive optional local reminders with used, discarded and snooze actions.
• Search, filter, browse a monthly calendar and view insights from your own records.
• Organize household profiles and custom categories.
• Export full ZIP backups with photos or transfer records with CSV.
• Choose light, dark or system themes.
No login, ads, subscription or mandatory internet connection. Barcode scanning does not reveal batch expiry dates. Date recognition is not guaranteed; always verify the label. Android battery restrictions may delay reminders. Uninstalling removes local data unless you have exported a backup.

## Permission disclosure
Camera: optional scanning and packaging capture. Notifications: optional date reminders. WorkManager may add system scheduling/reboot/wake-lock permissions; these support persistent jobs, not tracking. Photo/document access is limited to selections through system pickers. No internet, location, contacts, SMS, microphone, broad-storage or exact-alarm permission should be present. Inspect the final merged manifest before upload.

## Data safety guidance
If the final bundle still matches this implementation, app data is processed on device and the app does not collect/share it off device. On-device processing does not count as collection under Google's definition. User-directed external backup destinations are selected by the user. Review Google's current definitions and SDK disclosure guidance; do not copy these choices if you later add telemetry, ads, internet, crash reporting or cloud features. Declare optional access to photos/camera as appropriate in Console permissions fields. Provide the privacy policy publicly and in-app. No account-deletion web page is required for a version that creates no accounts. Add a real support email.

## Before release
- Install on Android 9 and a current Android version; finish the test matrix in TEST_REPORT.md.
- Verify notifications after reboot, force-stop recovery after reopening, permission denial and time-zone changes on actual devices.
- Test barcode and OCR in airplane mode from first launch, including a device without Google Play Services.
- Check 16 KB page compatibility for every bundled native library. Do not submit if the release checker fails.
- Verify release R8 shrinking preserves Room, serialization, ML Kit and barcode flow.
- Capture real screenshots: empty home, populated home, editor, calendar, insights and settings. No fabricated stats or render-only screenshots.
- Use the included original `store-assets/play-icon-512.png` and `store-assets/feature-graphic-1024x500.png`; verify them in the Play listing preview.
- Set Productivity category and complete content rating, audience and ads declarations accurately (no ads).
- Check developer-account testing requirements in your Console. Required tester counts/durations depend on account eligibility; no blanket testing guarantee is made.
- Run internal/closed testing and address crashes, Android Vitals, accessibility and policy feedback before production rollout.
